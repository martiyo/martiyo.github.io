Git remoto con Codeberg y gestor de contraseñas pass

Configuración completa para versionar un proyecto en Codeberg usando git local y autenticar los push/fetch con el token guardado en el gestor de contraseñas `pass` (cifrado con GPG), en lugar de tenerlo en texto plano.

Resumen de lo visto: cómo crear el entorno virtual, inicializar el repo, subir a Codeberg y cambiar la autenticación de `git credential store` (texto plano) a `pass-git-helper` (cifrado con GPG).

Crear el entorno virtual del proyecto

Es buen hábito crear un venv propio por proyecto para llevar un control de dependencias limpio: 

cd ~/storage/dev/python/streamlit/workDaySync
python3 -m venv .venv
source .venv/bin/activate
pip install streamlit streamlit-calendar pandas

Nota: si la conexión es lenta, pip puede abortar la descarga de wheels grandes (como `pyarrow`, 48 MB) por su timeout. Se puede descargar el wheel con `curl` y luego instalar desde el archivo local: 

curl -L -o pyarrow-24.0.0-cp311-cp311-manylinux_2_28_x86_64.whl \
  https://files.pythonhosted.org/.../pyarrow-24.0.0-cp311-cp311-manylinux_2_28_x86_64.whl
./.venv/bin/pip install ./pyarrow-24.0.0-cp311-cp311-manylinux_2_28_x86_64.whl

Crear el archivo .gitignore

Ignora entornos, caches de Python y datos locales del usuario: 

.venv/
__pycache__/
*.py[cod]
.streamlit/
data/

Iniciar el repositorio git

$ git init -b main
$ git add -A
$ git commit -m "workDaySync: app Streamlit multipágina"

Crear el repo en Codeberg y conectar el remote

Se crea el repo vacío en https://codeberg.org (o con la API) y se añade el remote: 

git remote add origin https://codeberg.org/USUARIO/workDaySync.git

Verificar el remote: 

git remote -v
git ls-remote --heads origin

Subir (push) inicial

git push -u origin main

La primera vez Codeberg pide autenticación. No se usa la contraseña de la cuenta sino un token de acceso personal (Settings → Applications → Generate new token).

Autenticación: de texto plano a pass

El problema del helper store

Con `git config credential.helper store` git guarda las credenciales en `~/.git-credentials` en texto plano. Funciona pero expone el token.

Solución con pass + pass-git-helper

La alternativa es usar el gestor de contraseñas `pass` (que cifra con GPG) y un helper que asocie el dominio de git con una entrada. Se necesita:

  • `pass-git-helper` (instalado con apt).
  • Una entrada en `pass` cuyo `password` (primera línea) sea el token.
  • Un archivo de mapping que asocie `codeberg.org` con esa entrada.
  • Cambiar el helper de git y limpiar el remote y `~/.git-credentials`.

Instalar el helper: 

sudo apt-get install -y pass-git-helper

Crear la entrada en pass con el token (pide el passphrase de GPG para cifrar): 

echo 'TOKEN_CODIDO' | pass insert -m codeberg-git

Crear el mapping `~/.config/pass-git-helper/git-pass-mapping.ini`: 

[codeberg.org]
target=codeberg-git

Configurar git para usar el helper y limpiar las credenciales en texto plano: 

git config credential.helper '!f() { echo "username=martinc2688"; pass-git-helper "$@"; }; f'
git remote set-url origin https://codeberg.org/martinc2688/workDaySync.git
rm -f ~/.git-credentials

Probar que la autenticación funciona: 

git fetch origin

Desde ahora, cada operación git desencripta el token de `pass` (pidiendo el passphrase de GPG o usando el mejor agente) y ya no hay ningún secreto en texto plano en el sistema.

Conclusión

  • Entorno virtual por proyecto para control limpio de dependencias.
  • Versión con git y remote en Codeberg.
  • Autenticación segura con `pass` + GPG, evitando tokens en texto plano.
  • En futuros push de este repo ya no se necesita ninguna configuración manual.
